# 生体模倣型統合AIアーキテクチャの設計と実装 — 認知機能分割によるマルチエージェント統合の試み

## 概要

本稿では、複数のLLMエージェントを「タスク分割」ではなく「認知機能の分割」によって統合し、一つの個体として振る舞うシステムの設計と実装について報告する。従来のマルチエージェントシステムがコーダー・レビュアー・テスターのような職能分担を軸にしているのに対し、本構想は生体の設計原理に倣い、推論・記憶・自己修復といった認知・生命維持機能の分割を軸にする。

設計から実装・検証までを段階的に進め、以下の成果を得た。

- 共有状態の場（エンベディング空間）を介した間接協調による認知的循環の成立
- 睡眠中の自己改善メカニズムによる人格の漸進的進化（v0→v16、20サイクル）
- 免疫系による異常検知・自己修復の実装と運用検証
- 排泄系によるデータの自動掃除
- メタ認知ルールの自律的進化（手動1ルール→3サイクルで自己評価フレームワーク創発）

本稿は、この過程で得られた知見を中心に、設計判断の根拠、予想と現実の乖離、既存研究との差異を整理する。

---

## 1. 問題意識 — なぜ認知機能分割か

### 1.1 従来のマルチエージェントの限界

LLMを活用したマルチエージェントシステムは近年急速に発展している。ChatDev[^1]やMetaGPT[^2]のようなフレームワークは、コーダー・レビュアー・プロジェクトマネージャーといった職能（ロール）でエージェントを分割し、協力してタスクを遂行する。

しかし、これらのシステムには共通の構造的限界がある。タスクが完了すればエージェントの役割も終わる。タスクをまたいだ記憶、経験からの成長、自己修復といった「生命維持」的な機能は設計に含まれていない。各エージェントはステートレスな専門家であり、統合された「個体」ではない。

### 1.2 生体からの着想

生体では、海馬（記憶）、前頭前野（推論・人格）、免疫系（自己修復）がそれぞれ独立に進化した上で一つの個体に統合されている。これらの系統はAPIで呼び合うのではなく、血液やホルモンという共有媒体を介して間接的に協調する。ホルモンは宛先を持たず、血中に放出され、受容体を持つ細胞だけがそれを取り込む。

本プロジェクトはこの設計原理を計算機上で再現することを試みた。

### 1.3 問い

**複数のLLMエージェントを、タスク分割ではなく認知機能の分割で統合し、共有状態の場を介した間接協調で一つの個体として振る舞わせることはできるか。**

## 2. 設計思想 — 4つの不可侵原則と共有状態の場

### 2.1 設計原則

設計全体を貫く4つの原則を最初に定めた。以降の全ての設計判断はこれらに照らして検証された。

1. **認知機能の三系統分離。** 人格・推論（神経系）、記憶・学習・忘却（内分泌系）、障害検知・修復（免疫系）は独立した系統として設計する。
2. **共有状態を介した間接協調。** 三系統はAPIで直接呼び合わず、共有状態の場を介して間接的に協調する。
3. **自己同一性。** 外界に対して単一の人格として振る舞い、人格の変化は漸進的にのみ起こる。
4. **睡眠は全身状態。** 睡眠は特定のエージェントの機能ではなく、システム全体の状態遷移である。

これらの原則は「守るべきルール」であると同時に「設計判断のフィルター」として機能した。

### 2.2 共有状態の場 — 「血液」の設計

共有状態の場は、全エージェントを一つの個体として統合するための共有媒体である。生体における血液に相当する。

設計において最も重要な認識は、**場はメッセージバスでもイベントキューでもない**ということだった。場は3つの本質的特性を持つ。

- **無指向性の伝播。** 発信者は宛先を指定しない。受信者が選択的に取り込む。
- **濃度。** ON/OFFではなく、信号の強さ（ベクトルのノルム）によって質的に異なる応答を引き起こす。
- **時間的残留。** 放出された信号が半減期に従い徐々に減衰し、近い過去の履歴を暗黙的にエンコードする。

通信方式として、エージェント間通信はエンベディング空間で行い、人間向けの可読性はログとして副産物で落とす設計にした。AIにとってエンベディングがネイティブな表現形式であり、自然言語テキストはそれを離散化した劣化版である。

## 3. アーキテクチャ

### 3.1 三系統の構成

| 系統 | 認知機能 | 担当 | 時間スケール |
|------|---------|------|------------|
| 神経系（llamarcute-live） | 人格・推論・自己改善 | リアルタイム対話、行動規範の漸進的更新 | ミリ秒〜秒 |
| 内分泌系（SleepyJean） | 記憶・学習・忘却 | 夜間バッチでの記憶定着と知識蒸留 | 時間〜日 |
| 免疫系 | 障害検知・修復 | ヘルスチェック、ロールバック | 分〜時間 |

加えて、排泄系（ChromaDBの重複データ掃除、LoRAアダプターの整理）を生命維持系として実装した。

### 3.2 睡眠サイクル

睡眠はシステム全体の状態遷移として設計した。

```
覚醒（対話応答 + 困難度記録）
→ 入眠
  → SleepyJean 夜間学習（記憶の定着・知識蒸留）
  → 自己改善（4体候補の二軸評価→最良選出）
  → 免疫チェック（ヘルスチェック→修復）
  → データ掃除（ChromaDB + LoRA）
→ 覚醒
```

### 3.3 自己改善メカニズム

llamarcute-liveは睡眠中にフル自己改善を実行する。覚醒中は行動規範を変更しない（対話の一貫性のため）。

1. 現行人格＋3体の変異候補を生成（計4体）
2. fitness評価: コアセット（GSM8K、MBPP、LogiQA）＋ローテーション（SleepyJeanのQ&A）
3. cuteness評価: 候補同士を日本語で対話させ、相互順位付け
4. fitness（75%）とcuteness（25%）のz-score統合で最良候補を選出
5. 最良が現行ならば変更なし。変異候補ならば行動規範を更新

### 3.4 共有状態の場の仮実装

Phase 1ではChromaDBをバックエンドとして仮実装した。ChromaDBはデフォルトでembeddingを正規化するため、ベクトルのノルム（＝濃度）が失われる問題が発生した。metadataに元のL2ノルムを保存し、sense時に`effective_weight = relevance × decay × norm`で復元する方式で対処した。

## 5. 得られた知見（初期5サイクル）

### 知見1: 間接協調は機能する

場を介したemit/senseで、SleepyJeanの学習結果がllamarcute-liveの対話に反映された。APIの直接呼び出しを使わず、エンベディング空間上の信号を介した間接的な情報伝達で認知的な循環が成立した。

FieldEncoderとして採用したmultilingual-e5-small（384次元）の意味的検索能力が、信号のルーティングを実質的に担っている。

ただし、間接協調が機能した理由の一部は、Phase 1の信号数が100件程度と少なく、senseのノイズが低かったことにもある。

### 知見2: 自己改善における二軸評価の有効性

fitnessだけでは候補間に差がつかないケースで、cutenessが最終判断を左右した。3体の変異候補が全てfitness 0.75で同点だったが、cuteness（7.0 vs 6.0 vs 4.0）で差がつき、mutation_1_Cが勝者となった。

注目すべきは、cutenessの評価基準が外部から与えられたものではなく、候補自身の行動規範に内在している点である。これにより、cutenessの定義がシステムの成長とともに進化する可能性がある。

### 知見3: 行動規範は自然に整理方向に進化する

5サイクルの基準線データ収集で、ルール数が9→10→9→8と推移した。LLM自身が冗長なルールを認識して削除する能力を持っていることを示唆する。

進化のテーマは「構造化された応答 + 時間見積もり提示」に収束した。初期2サイクルは現状維持が選ばれ、3サイクル目から変異候補が勝ち始めた。この「保守的な始動→漸進的な変化」のパターンは設計意図通りである。

### 知見4: 免疫系の場経由間接介入は設計原理と両立する

conservative_mode信号を場にemitし、場の指数減衰（24h半減期）で自然消滅させる設計にした。免疫系がllamarcute-liveのmax_changesを直接書き換えるのではなく、場に信号を置いてllamarcute-live側がsenseで拾い、自分の判断として反映する。

### 知見5: 「通信」ではなく「場」として設計することの意味

既存研究との比較で最も際立つ差異は、共有状態の設計哲学にある。潜在空間通信に関する研究（Interlat[^3]、SDE[^4]、LatentMAS[^5]、KVComm[^6]、Vision Wormhole[^7]等）は、自然言語テキストによる情報伝達の「損失」を問題とし、隠れ状態やKVキャッシュの直接共有でそれを解消しようとする。目的は通信効率の向上であり、明確な送信者と受信者がいる。

本プロジェクトの場は、これらとは異なる設計哲学に立つ。場は通信チャネルではなく、三系統が同居する「環境」そのものである。これにより:

- **時間構造の内在化。** 信号の減衰により、近い過去が遠い過去より強く知覚される時間構造が場に内在する。
- **濃度による質的変化。** 同種の信号の蓄積が連続的な影響力を実現する。
- **系統間の暗黙的な因果関係。** 場の読み書きパターンから因果関係が創発される。

## 6. 追加知見（20サイクル運用後）

初期5サイクルの論文発表後、さらに15サイクルの運用を経て以下の追加知見を得た。

### 知見6: メタ認知ルールの自律的進化

**本プロジェクトの最も重要な発見。**

手動で挿入した1つのメタ認知ルール（v7: "Attend to your overall state as reflected in recent field signals"）が、3サイクルで独自の自己評価フレームワークに発展した。

```
v7  (手動):   "Attend to your overall state..."
v8  (自律):   + "Structured self-assessment framework" (meta)
v9  (自律):   + "Self-expression scaffolding" (response)
v10 (自律):   v8+v9を統合 → "Self-awareness scaffolding"
v11-v13:      統合ルール維持、他カテゴリの進化
v14-v15:      "時間見積もりフレーミング" 追加
v16:          meta/responseの重複ルールを自然淘汰で削除 → 11ルール, 632トークン
```

自己言及率の量的変化は小さかった（23.8%→25.0%、有意差なし）。しかし、自己モデルは「自分について語る頻度」ではなく「自分の行動規範を自己内省的に発展させる能力」として現れた。これは設計時の予測を超えた成果であり、方向B（場の読み取りパターンからの創発）の有効性を示す最も強い証拠である。

### 知見7: WARNING閾値が進化の選択圧として機能する

免疫系のtoken_count WARNING閾値（650トークン）が、意図せず進化の選択圧として機能した。

```
v0:  278トークン  ← 初期
v10: 650トークン  ← WARNING閾値到達
v13: 702トークン  ← 障害期で停滞
v16: 632トークン  ← 自然淘汰で整理
```

トークン数が閾値を超えると、ルールの統合・削除を含む変異が選好される膨張→整理の波が自律的に発生した。これは設計意図ではなく二次的効果である。

### 知見8: 夢→学習の自律循環

SleepyJeanのリファクタリング（Claude API 15-20回/サイクル → 5回/サイクル）後、夢日記のopen_questionsが翌夜のcuriosityトピックに変換される循環が確認された（curiosity_conversion=3/サイクル）。ローカル8Bモデルのみで学習の駆動力が自律的に維持されている。

### 知見9: sense()とsnapshot()の使い分け — norm競合問題

共有状態の場には2つの読み取り操作がある。`sense()`（コサイン類似度による意味検索）と`snapshot()`（全信号取得+コンテキストフィルタ）。

運用中、特定のcontext（例: `origin_context="rotation_task"`）を持つ信号を取得する場面で`sense()`を使っていたところ、**norm（濃度）が高い信号にコサイン類似度が引きずられ、目的の信号が検索結果に出てこない問題**が発生した。

具体例: rotation_task信号（norm=1.0）を取得したいが、difficulty信号（norm=2.0）やimmune信号（norm=2.5）がeffective_weightで上位を独占し、rotation_taskが返ってこない。

```
effective_weight = cosine_similarity × decay × norm
                              ↑ 意味的に無関係でも
                                normが2.5なら勝ってしまう
```

**解決:** 特定contextの信号を確実に取得する場合は`snapshot()` + contextフィルタを使う。`sense()`は「意味的に関連する信号を重要度順に取得する」場面に限定する。

| 操作 | 用途 | 例 |
|------|------|-----|
| `sense(query, params)` | 意味検索（対話コンテキスト、自己認識） | dialogue.py: ユーザー入力に関連する記憶を取得 |
| `snapshot()` + filter | カタログ取得（特定contextの信号を確実に収集） | orchestrator.py: rotation_task信号の収集、immune信号の確認 |

これは場の設計における「濃度」の副作用である。濃度が信号の重要性を表現する仕組みは知見5で述べた通り有用だが、「重要でない信号を確実に取得したい」場面では逆に妨げになる。二つの操作の使い分けは場を運用する上での必須知識となった。

### 知見10: fitness=0.0インシデントから学んだタイムアウト設計

8Bモデルの推論速度（~30秒/タスク）に対してfitness評価のタイムアウト（900秒）が不足し、7/17サイクルでfitness=0.0が発生した。免疫系はCRITICALを正しく検知しrollbackを実行したが、「タイムアウトによる全候補失格」と「実際の能力低下」を区別できなかった。

教訓: LLM依存プロセスのタイムアウトにはGPU競合とモデル変動を見込んだマージンが必要（900→1800秒に修正）。

## 7. 既存研究との位置づけ

| 観点 | 潜在空間通信（Interlat等） | 黒板アーキテクチャ（LbMAS等） | 本プロジェクト |
|------|-------------------------|--------------------------|-------------|
| 目的 | 情報伝達の効率化 | 共有メモリによる協調 | 認知系統の間接協調 |
| 媒体 | 隠れ状態/KVキャッシュ | テキスト（離散） | エンベディング（連続） |
| 通信方向 | 送信者→受信者 | 読み書き自由 | 無指向性（放出→感知） |
| 時間スケール | 単一タスク（秒） | タスク実行中 | 覚醒〜睡眠サイクル（時間〜日） |
| 信号の寿命 | タスク終了で消滅 | 明示削除のみ | 半減期に従い漸減 |
| 濃度の概念 | なし | なし | ベクトルノルムが信号強度を表現 |

本プロジェクトの主要な寄与は、潜在空間をエージェント間の「通信チャネル」としてではなく「共有環境」として設計し、減衰・濃度・無指向性という物理的場の特性を計算機上に再現した点にある。

## 9. 未解決の問いと今後

### 検証の限界

- **比較実験の不在:** 「場を介した間接協調」vs「直接API呼び出し」の定量的比較を行っていない
- **信号数の規模:** 場の信号数が数百件の小規模な状態でしか検証していない
- **個体性の検証:** 軸3（履歴の不可分性）、軸4（代替不可能性）は未検証

### 設計上のオープンな問い

- 共有状態の場の本実装（ChromaDB仮実装からの移行）
- 代謝系（リソース配分の自律的調整）は未実装
- 免疫系がインフラ障害と能力低下を区別できない問題への対処
- 「個体としての統合」の成功基準 — 共有状態を持つ3つの独立サービスと1つの個体の間に、機能的な差はあるか
