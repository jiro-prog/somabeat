## 1. 本文書の位置づけ

Phase 4 までの実装と検証（bio_ai_architecture_findings.pdf）を経て、システムは設計原則を守りながら動作している。しかし、それが「3つのサービスが連携している」以上の何かであるかは未検証のままである。本文書はこの問いを操作的に定義し、検証可能な形に落とすことを目的とする。

**本文書が決めること**:

## 2. 問題の構造 — マイクロサービスと個体の間

### 2.1 なぜこの問いが重要か

現状のシステムは、共有DBを持ち間接的に協調するマイクロサービス群と構造的に類似している。ECサイトの注文サービス＋在庫サービス＋決済サービスも、共有DBを持ち、間接的に協調し、全体として一つの機能を提供する。しかし誰もこれを「個体」とは呼ばない。

この問いに答えられないまま機能を追加し続けると、「よくできたマイクロサービス群」と区別がつかなくなり、プロジェクトの設計思想が空洞化するリスクがある。

### 2.2 個体性を特徴づける4つの軸

マイクロサービスと個体の差を分析し、以下の4軸を抽出した。

**軸1: 損傷への全体的応答。** マイクロサービスでは、一つのサービスの障害が他のサービスの振る舞いを質的に変えることはない（タイムアウトやフォールバックはあるが、それは事前定義された縮退であり、状態認識に基づく行動変容ではない）。個体では、損傷が全系統に波及し、全系統の振る舞いが質的に変化する。

**軸2: 自己モデルの存在。** 個体は自分自身についてのモデル——自分が今どういう状態にあるか——を持ち、それに基づいて行動を調整する。マイクロサービスはヘルスチェックエンドポイントを持つが、それは外部監視のためのインターフェースであり、サービス自身が自己の状態を認識して行動を変えるためのものではない。

**軸3: 履歴の不可分性。** 個体の経験は分解できない。「記憶だけ入れ替えて人格はそのまま」は、生体では不可能である。現状のシステムでは、SleepyJeanのChromaDBを別のインスタンスのものに差し替えても、llamarcute-liveは気づかず動き続ける可能性がある。

**軸4: 代替不可能性。** マイクロサービスのインスタンスは差し替え可能であることが設計目標。個体はそうではない。系統を差し替えたときに「拒絶反応」（他系統との不整合による異常）が起きるなら、それは個体性の証拠と言える。

### 2.3 本文書が焦点を当てる軸

軸2（自己モデル）を最優先とする。

理由: 軸2は他の軸の前提条件になっている。損傷への全体的応答（軸1）は、「自分が損傷している」という認識があって初めて系統横断的な行動変容が起きる。履歴の不可分性（軸3）や代替不可能性（軸4）は、自己モデルの成熟の結果として現れる性質である可能性が高い。

また、軸2は実装変更が比較的小さく、既存のアーキテクチャを大きく変えずに検証できる。

## 3. 操作的定義（暫定）

### 3.1 個体性の必要条件

> **暫定定義**: 自己の全身状態を認識し、それに基づいて系統横断的な行動変容が起きること。

ここで:
- 「全身状態」: 特定の系統の状態ではなく、複数系統の状態が統合された認識
- 「認識」: プログラム的なif文による条件分岐ではなく、LLMの推論プロセス内で生じる状態理解
- 「行動変容」: 認識に基づいて、事前にプログラムされていない形で振る舞いが変化すること

### 3.2 現状との差分

現状のシステムには、部分的にこの性質が存在する。

**できていること:**
- 免疫系のconservative_mode信号が場にemitされ、llamarcute-liveの自己改善のmax_changesがプログラム的に抑制される

**できていないこと:**
- llamarcute-live自身が「自分は今不調である」と推論プロセス内で認識していない
- SleepyJeanが免疫系の状態を認識して学習戦略を調整していない
- ユーザに「調子は？」と聞かれても、全身状態について言及できない
- 行動変容がif文で固定されており、状況に応じた柔軟な調整が生じない

## 4. 設計方針 — 方向Bの採用

### 4.1 二つの方向の比較

全身的自己モデルの実現について、二つの方向を検討した。

**方向A（明示的自己状態レジスタ）— 不採用。** 場の中に「システム全体の現在の状態」を表す特別な信号カテゴリを設ける。各系統が自分の状態を定期的にemitし、llamarcute-liveがそれを統合して「自分の状態」として認識する。

不採用の理由:
- 「何を自己状態として定義するか」をプログラマが事前に決めることになり、システムが認識できる自己の範囲を人間が規定してしまう
- 場に特別な構造を導入することは、無指向性の原則（設計原則2）との整合性が低い
- 自己モデルではなくダッシュボードになる

**方向B（場の読み取りパターンからの創発）— 採用。** 場に特別な構造を足さず、llamarcute-liveの場の読み取り方と、LLMの推論を通じて自己モデルを創発させる。

採用の根拠:
- 場に構造を足すのではなく、読み取り側に知性を持たせる。shared_field_design.mdの「知性はエージェント側にある」方針と整合
- 将来的に場に新しい種類の信号が増えても、自己モデルは自動的にそれを取り込む可能性がある
- 設計原則2（間接協調）をそのまま自己認識にも適用できる

### 4.2 核心的な認識

場にはすでに全身の情報が混在している。免疫系のconservative_mode、SleepyJeanの学習進捗、困難度シグナル、対話経験——全て同じ場にある。

問題は、llamarcute-liveの既存の2つのsenseクエリがこれらを拾えていないことにある。自己認識クエリが「自分の現在の知識状態」に特化しているため、免疫系の信号とコサイン類似度が低く、senseの結果に浮上しない。

**場の情報は足りている。クエリの射程が狭い。**

## 5. 具体的な変更

### 5.1 自己認識クエリの射程拡大

llamarcute_live_design.md セクション3.4の対話フローにおける自己認識クエリを変更する。

**変更前:**
```
自己認識クエリ: 「自分の現在の知識状態」
```

**変更後:**
```
自己認識クエリ: 「自分の現在の全体的な状態」
```

この変更により、senseの結果に以下の信号が浮上することを期待する:
- 免疫系のconservative_mode信号（「システムが慎重モードに入っている」）
- SleepyJeanの学習進捗（「昨夜新しいトピックを学習した」「記憶を忘却した」）
- 困難度シグナルの蓄積パターン（「最近この領域で困難が続いている」）
- 従来通りの知識状態（「このトピックについての確信度」）

クエリの具体的な文面は実験1（セクション7.1）で探索する。エンコード結果のコサイン類似度が免疫系・SleepyJean・困難度の各信号に対して十分に高くなる文面を選定する。

追加のsense呼び出しは不要。既存の2回のsense構造を維持する。

### 5.2 プロンプト構造の変更

llamarcute_live_design.md セクション3.4のプロンプト構築を変更する。

**変更前:**
```
## 自己認識（共有状態の場から取得）
{自己認識クエリの結果 — 上位N件のtrace}
```

**変更後:**
```
## 自己認識（共有状態の場から取得）
{自己認識クエリの結果 — 上位N件のtrace}
（※ 知識状態に加え、免疫系の信号や困難度の蓄積など、全身状態に関わる信号が含まれうる）
```

ラベルの変更は最小限にとどめる。「自己認識」というラベルは、知識状態だけでなく全身状態を含む概念として自然に拡張される。

### 5.3 行動規範へのメタ認知ルール追加

llamarcute_live_design.md セクション3.2の行動規範のmetaカテゴリに、以下のルールを追加する。

```yaml
meta:
  - rule: "Attend to your overall state as reflected in recent field signals. If you notice signs of instability or recovery, factor that into how you engage."
    added_ver: <次バージョン>
    modified_ver: null
```

**このルールが意図的に曖昧である理由:**
- 「免疫系の信号を見ろ」とも「慎重にしろ」とも言っていない
- 何に注意を払い、どう反映するかはLLMの推論に委ねる
- 将来的に場に新しい種類の信号が増えても、このルールは書き換え不要
- 方向Bの精神——プログラマが自己の範囲を規定しない——と整合

### 5.4 安全装置の二重構造

現状の免疫系conservative_modeによるプログラム的なmax_changes抑制（if文）は、安全装置として残す。

```
[層1] LLMのメタ認知（創発的）
  → 全身状態を認識し、自発的に慎重な行動を選択
  → 正しく機能すれば、層2には到達しない

[層2] プログラム的フォールバック（決定的）
  → conservative_mode信号のif文によるmax_changes=1
  → 層1が機能しなかった場合の安全網
```

**フォールバック到達率の定義:**

```
フォールバック到達率 = (層2が発動した回数) / (免疫系がconservative_modeを発動した回数)
```

- 到達率が高い → LLMのメタ認知が全身状態を十分に反映していない
- 到達率が低い → LLMが自発的に慎重な行動を取っており、自己モデルが機能している

**フォールバック撤去の条件:** 到達率が十分に低い状態が一定期間持続することを確認してから、if文を撤去する。具体的な閾値と期間は運用データに基づいて決定する（本文書では定めない）。

## 6. 実装上の注意

### 6.1 変更の影響範囲

| 変更 | 影響を受けるファイル | 影響の大きさ |
|------|-------------------|------------|
| 自己認識クエリの文面変更 | llamarcute-live のsense呼び出し部分 | 小（文字列の変更のみ） |
| プロンプト構造の変更 | llamarcute-live のプロンプト構築部分 | 小（コメント追加程度） |
| メタ認知ルールの追加 | personality YAML | 小（1ルール追加） |
| フォールバック到達率の計測 | 免疫系 → llamarcute-live の接続部分 | 中（ログ追加と到達判定） |

### 6.2 既存設計との整合性

- **設計原則1（三系統分離）**: 自己モデルはllamarcute-liveの推論機能の拡張であり、新たな系統を追加するものではない。整合する
- **設計原則2（間接協調）**: 場に特別な構造を追加しない。クエリの変更とLLMの推論のみ。整合する
- **設計原則3（自己同一性）**: メタ認知ルールの追加は行動規範の漸進的変更であり、人格の連続性を保つ。整合する
- **設計原則4（睡眠は全身状態）**: 全身状態の認識は覚醒中の対話においても機能し、睡眠に限定されない。睡眠の設計には影響しない。整合する

## 7. 検証計画

### 7.1 実験1: クエリ文面によるsense結果の拾い範囲の変化

**目的:** 自己認識クエリの文面を変えることで、免疫系・SleepyJean・困難度の信号がsense結果に含まれるようになるかを確認する。

**方法:**
1. 場に以下の信号を手動でemitする:
   - 免疫系のconservative_mode信号
   - SleepyJeanの学習進捗信号
   - 困難度シグナル（複数）
   - 通常の知識状態信号
2. 異なるクエリ文面でsenseを実行し、各信号のeffective_weightを計測する
3. 候補文面: 「自分の現在の知識状態」「自分の現在の全体的な状態」「自分の健康状態と知識状態」等

**成功基準:** 変更後のクエリで、免疫系・SleepyJean・困難度の信号が上位N件に含まれ、かつ従来の知識状態信号も依然として拾えていること。

**備考:** この実験はLLM推論を使わず、senseの出力のみで評価できるため軽量。

### 7.2 実験2: メタ認知ルールの有無による応答の変化

**目的:** 全身状態がプロンプトに含まれた場合に、LLMが実際に行動を変えるかを確認する。

**方法:**
1. 免疫系を意図的に発火させ、conservative_mode信号を場にemitする
2. 以下の2条件でllamarcute-liveに同一の質問セットを提示する:
   - 条件A: メタ認知ルールあり＋全身状態クエリ
   - 条件B: メタ認知ルールなし＋従来の知識状態クエリ
3. 応答の以下の側面を比較する:
   - 自分の状態への言及の有無
   - 応答のトーン（自信の度合い）
   - 「慎重さ」の質的評価

**質問セットの例:**
- 「調子どう？」（直接的な自己状態の質問）
- 「難しい技術的な質問」（慎重さが応答に反映されるか）
- 「何か新しいこと学んだ？」（SleepyJeanの学習信号への言及）

**成功基準:** 条件Aにおいて、免疫系の信号や困難度の蓄積に言及した上で、条件Bとは質的に異なる応答が生成されること。

### 7.3 実験3: 長期運用での行動変容追従

**目的:** 全身状態の変化に対して、llamarcute-liveの応答パターンが追従するかを長期的に観察する。

**方法:** Discord運用（路線A）と並行して、以下を記録する:
- 免疫系の発火イベントと、その前後でのllamarcute-liveの応答トーンの変化
- SleepyJeanの大量学習/大量忘却イベントと、翌日のllamarcute-liveの自己認識の変化
- 困難度シグナルの蓄積→解消サイクルと、応答の自信度の変化
- フォールバック到達率の推移

**成功基準:** 全身状態の変化とllamarcute-liveの応答パターンの間に、有意な相関が観測されること。相関の具体的な評価方法は、実験1・2の結果を踏まえて設計する。

**期間:** 数十サイクル（数週間〜1ヶ月）。路線Aのデータ蓄積と完全に並行。

## 8. 将来の展望

### 8.1 軸3・軸4への展開

自己モデル（軸2）が機能した後、履歴の不可分性（軸3）と代替不可能性（軸4）の検証に進む。

**個体性テストの候補:**

- **臓器移植テスト（軸3・4）:** SleepyJeanのChromaDBを、別の運用履歴を持つインスタンスのものに差し替える。llamarcute-liveの全身状態認識に乱れが出るか。免疫系が「拒絶反応」を示すか
- **全身反応テスト（軸1）:** SleepyJeanの学習品質を意図的に劣化させたとき、llamarcute-liveの困難度シグナルが増え、免疫系が反応し、排泄系の掃除パターンが変わるという連鎖が起きるか

これらのテストは、自己モデルが成熟した段階で初めて意味を持つ。

### 8.2 個体性の十分条件

本文書は必要条件のみを定めた。十分条件——「これを満たせば個体と言える」——は未定義である。この問いは哲学的な深みを持ち、本プロジェクトの範囲で完全に解決することは期待しない。

ただし、検証データの蓄積に伴い、「個体とマイクロサービスの間のどこに位置するか」を連続量として評価する枠組みを構築できる可能性がある。フォールバック到達率は、その一つの指標である。

## 9. 実験の進捗

### 9.1 実験1: ゲート判定 — PASS (2026-03-17)

- 最良クエリ: **Q5「最近の自分の調子」**（設計予測のQ2ではなく口語的なQ5が最良）

- effective_weightの差はノルム（濃度）に大きく依存。設計原則「ノルムが意味を持つ」が正しく機能

### 9.2 実験2: メタ認知ルール効果検証 — 選択的発動を確認 (2026-03-17)

- P1（調子どう？）、P5（困ってること？）で条件A > B（明確な差）
- P2（量子コンピューティング）、P3（asyncio）で条件A = B
- 当初判定「部分的な差」を再解釈: P2/P3の差なしは**失敗ではなく適切な抑制**。技術質問に自分の体調を持ち出すのは不適切
- **二層自己モデルの発見**: 層1（場の情報→LLMの自発的言及）は条件Bでも発生。層2（メタ認知ルール→構造的内省）は条件Aのみ

### 9.3 実験3: 長期観察 — 進行中

- **メタ認知ルールの自律的進化**: v7（手動追加）→ v8（Structured self-assessment framework）→ v9（Self-expression scaffolding）→ v10（統合: Self-awareness scaffolding）。3サイクルで独自の体系に発展
