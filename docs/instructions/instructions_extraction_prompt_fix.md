# トリプル抽出プロンプト改善 — タスク指示

**作成日:** 2026-04-01
**前提:** Phase 3完了（276件PASS）。KGに9ノード7エッジが格納済みだが、抽出内容の大半がハルシネーション
**根拠:** 現行プロンプトが「事実を抽出せよ」としか指示しておらず、Qwen3-8B GPTQが対話に書かれていない情報を自身の知識から補完している

---

## 問題

現行の抽出結果（chunk_0から）:

| subject | relation | object |
|---------|----------|--------|
| フォレトス | 分布地 | アリゾナ州 |
| フォレトス | 生態特性 | 砂漠环境での生存 |
| フォレトス | タイプ | ポケモン |
| フォレトス | 特徴 | 葉っぱを持つ |
| フォレトス | 叫称 | 「森の守る者」 |
| フォレトス | 所在場所 | 森や草原 |
| ハルシネーション | 定義 | 人間の脳による情報補完の過程 |

元の対話で述べられた事実は「フォレトスはむし・はがねタイプ」等だが、「アリゾナ州」「砂漠環境」「葉っぱを持つ」「森の守る者」はLLMが捏造した情報。7エッジ中、正確なのは1-2件のみ。

## タスク: 抽出プロンプトの改善

### 変更対象

`sleepyjean/triple_extractor.py` の `_build_extraction_prompt` メソッド

### 変更内容

system_promptを以下に差し替える:

```
あなたは対話ログから事実を抽出するアシスタントです。

【最重要ルール】
対話中に話者が明示的に述べた事実のみを抽出してください。
あなた自身の知識で補完・推測してはいけません。
対話に書かれていない情報は、たとえ事実であっても出力禁止です。

【除外対象】
- 挨拶、感想、主観的評価
- 対話に書かれていない背景知識や関連情報
- 話者が述べていない属性や特徴

【出力形式】1行1トリプル:
主語 | 関係 | 目的語

事実がない場合は「なし」とだけ出力してください。

【正しい抽出の例】
対話: 「フォレトスはむし・はがねタイプだよ」
正しい出力: フォレトス | タイプ | むし・はがね

【誤った抽出の例】
対話: 「フォレトスはむし・はがねタイプだよ」
誤った出力: フォレトス | 生息地 | 森（←対話に書かれていない。これを出力してはいけない）
誤った出力: フォレトス | 進化前 | クヌギダマ（←事実だが対話に書かれていない。これも出力禁止）
```

### 変更しないもの

- `_parse_triples` のパース処理（3列フォーマットは維持）
- `extract` メソッドのチャンク分割ロジック
- generate_bareの呼び出しパラメータ（temperature=0.3は維持）
- user_inputへの対話ログの渡し方

---

## テスト追加

`_build_extraction_prompt` の戻り値に以下の文言が含まれることを検証するテストを1件追加:

- system_promptに「あなた自身の知識で補完・推測してはいけません」が含まれる

既存テスト6件は変更不要（プロンプト文言のハードコードに依存していないはず。依存している場合は更新）。

---

## 検証手順

1. 全テストPASS（276件 + 新規1件）
2. KGをクリアする（`data/sleepyjean_kg.db` を削除 or テーブルをDROP）
3. botを起動し、以下の事実を含む対話を行う:
   - 「フォレトスはむし・はがねタイプだよ」
   - 「フォレトスはだいばくはつを覚えるよ」
   - 「ハルシネーションはLLMが事実でない情報を生成する現象だよ」
4. `/sleep` を実行
5. KGの内容を確認:
   - **PASS基準:** 各トリプルのobjectが対話で述べた内容と一致する。対話に書かれていない情報（生息地、進化前、分布地等）が含まれていない
   - **FAIL基準:** 対話に書かれていない情報がトリプルに含まれている → プロンプトのさらなる改善が必要。Soにエスカレーション
6. Reconsolidationのログ出力で抽出トリプル数を確認（対話3件から3-5トリプル程度が妥当。10件以上は過剰抽出の疑い）

---

## スコープ外

- 4列目（根拠発言）の追加 → 今回のプロンプト改善で不十分な場合に次のステップとして検討
- QualityGateの実装 → 別タスク
- 既存KGデータのクリーニング → KGクリア＋再抽出で対応（既存データの修正は行わない）

---

## エスカレーション基準

- プロンプト改善後もハルシネーションが3割以上残る場合 → 4列目（根拠付き出力）の追加を検討。Soに報告
- 「なし」の出力が多すぎる場合（事実を含む対話で抽出0件） → 制約が強すぎる。プロンプト調整が必要。Soに報告
